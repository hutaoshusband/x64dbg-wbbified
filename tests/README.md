# Debugger verification suite

Run `python tests/run_tests.py` from the repository root. This is the shared entry point for baseline, fixture, inventory, build and native regression checks. Helper modules and the inventory fixture are not separate test launchers.

## Phases

| Phase | Outcome checked |
| --- | --- |
| `baseline` | Existing external MCP functional suite and isolated PEB hiding controls |
| `functional` | Existing functional cases without the extra PEB control processes |
| `defects` | Actual target argument delivery and executable assembly patch; known external failures remain failures |
| `contracts` | Authenticated responses for every catalog tool with empty arguments and no target |
| `surface` | GUI-thread inventory of menus, widgets, commands and script providers; shipped plugin resource dialogs, menus and configuration keys |
| `fixtures` | Normal execution, argument, register, module, guard-page and memory references; native database persistence across fresh debugger processes |
| `inventory` | Source registration/form candidates reconciled with the captured legacy catalog and optional runtime surface |
| `build` | Fresh Release source builds of the GUI debugger, headless debugger and existing native fixtures |
| `native` | Existing headless regression bundles, preserving their assertion failures and process exit results |
| `mcp-contracts` | Fresh source-built x64/x32 common, broker, connector, worker bootstrap and references; independent schemas, native identities and IPC byte codec, actual Windows argument/environment delivery, bounded parsing and dependency probes |

`--arch x64`, `--arch x32` and `--arch all` select architectures. `--case` can be repeated; baseline case selections accept globs, while native selections use existing native bundle IDs. `--engine` selects TitanEngine, GleeBug, StaticEngine or all available backends for the native phase. `--list` lists cases without launching or writing artifacts. `--timeout` bounds requests and execution waits between 1 and 60 seconds. Defaults are x64, baseline, and 45 seconds.

```powershell
python tests/run_tests.py --phase build --arch all
python tests/run_tests.py --phase fixtures --arch all
python tests/run_tests.py --phase fixtures --arch all --case test_fixture_oracles
python tests/run_tests.py --phase fixtures --arch all --case test_native_argument_oracles
python tests/run_tests.py --phase fixtures --arch all --engine all --case test_native_patch_oracles
python tests/run_tests.py --phase native --arch all --case commandparser --case script_run_exit
python tests/run_tests.py --phase contracts
python tests/run_tests.py --phase surface
python tests/run_tests.py --phase surface --surface-provider native --arch all
python tests/run_tests.py --phase defects
python tests/run_tests.py --phase mcp-contracts --arch all
python tests/run_tests.py --phase mcp-contracts --arch all --cmake C:/tools/cmake/bin/cmake.exe
python tests/run_tests.py --phase mcp-contracts --arch all --msvc-toolset 14.44.35207
```

Install the pinned test-only dependencies in `tests/requirements.txt` in the Python environment used for the suite. `mcp-contracts` uses jsonschema; the database fixture uses pefile to resolve the actual export RVA independently of debugger output. The native contract fixture is declared in the real cmkr input and kept out of default executable builds. New CMake directories fetch HTTP, JSON, SQLite and JavaScript sources by fixed URL and SHA-256; dependency metadata and licenses are retained in the build receipt. `X64DBG_BUILD_MCP=OFF` disables these new development targets for existing debugger-only builds.

The native patch reference executes the same source-checked assembly function normally and under both source-built engines. Separate software, hardware and one-byte execute-memory breakpoints remain armed while tracked assembly changes the first opcode, actual calls produce 7/42/7, and undo restores logical original bytes and tracking. The function occupies an isolated executable image page. Independent OS reads distinguish INT3 from logical bytes, OS debug-register contexts verify the hardware slot, and OS page queries verify memory trapping before and after reads/writes/restoration. Seven CPU steps compare both native and OS instruction pointers and accumulators with the source function. A separate real backend write crosses a committed read-only execute-trapped page into a reserved page while a software breakpoint also overlaps its first page. Its failure, actual changed prefix, raw INT3, updated logical original byte and restored memory protection are verified. Clearing both breakpoints must retain the actual prefix bytes and original protection. GleeBug writes in page-bounded parts, rejects incomplete success and updates software originals for its actual partial prefix. This control records partial effects; it does not provide transactional rollback. Invalid syntax and overlong assembly text change neither; overlong native text currently supplies no error message. This bounded runtime reference leaves single-shot breakpoint variants, exact installed-span limits, transactional rollback/conflicts and disk persistence open. All checks share this launcher; `patch_checks.py` is an imported checker.

`--cmake` selects an existing CMake executable for this phase; other phases reject it. Without the option, the suite resolves CMake in the configured compiler environment. Every build records the selected CMake version and executable hash, the exact MSVC executable hash and the configure/build commands, including failed build attempts. Explicit forward-slash MSVC paths prevent another installed compiler from being selected. Automatic cmkr generation is disabled during verification so the recorded generated source remains fixed; regenerate CMakeLists.txt from cmake.toml before running the suite after a build-definition change. CMake handles manifest embedding while each executable retains an explicit `asInvoker` UAC setting. Actual build and runtime checks establish support for a selected toolchain; an executable selection does not establish a minimum compiler or older OS claim.

`--msvc-toolset` selects an exact installed version through the discovered Visual Studio environment for this phase. Only three numeric version components are accepted, and a different resolved version fails instead of silently falling back. The build receipt records both requested and actual toolsets. CMake 3.22.6 is the declared build floor because the inherited GleeBug target requires C++23 feature support. Native MCP uses MSVC 19.44.35228.0 as its supported compiler floor; lower or different compilers fail configuration explicitly. The dependency record separates vendor runtime requirements, the exercised Windows 10.0.19044 x64 host and unverified OS/host variants. Both x64 and x32 development executables run on that host; this does not establish a native 32-bit OS or completed product acceptance.

The common contract registry describes twenty-six shared data contracts. It validates precise decimal/hex strings, explicit target/paused/mutation identities, exclusive address/file forms, library revisions, bounded pages/deadlines, expected byte ranges, native process identities, IPC envelopes and structured errors/evidence/timings. Pointer-width range checks run after address resolution. Thread-sensitive operations still require their own thread precondition, and identity/grant/lease checks belong to the real owner executor; a syntactically valid context alone authorizes no effect.

Typed results distinguish completed, accepted, partial failure, failed, cancelled and unknown outcomes. Accepted results require a job ID and pending verification; completed jobs can retain their ID. Verified results require evidence; unverified results require a follow-up route. Partial failures require an effect journal and recovery route. Unknown results retain observed effects and require reconciliation. Each tool's data schema refines the shared result envelope; unknown result fields and contradictory outcome/error combinations are rejected.

The canonical operation registry currently declares all 200 proposed server, capability, client-context, control, debugger, target, execution, thread, exception, register, expression, stack, structure, memory, breakpoint, trace, disassembly, assembly, patch, file, module, symbol, analysis, annotation, database, setting, favorite, command, plugin, semantic GUI, library, script, job, event, artifact and diagnostics tools. One definition binds each tool's schemas, effects, conditional effects, executor, requirements, completion predicate, recovery routes, acceptance references and handler. An administrator start requires the additional elevation effect; explicit file replacement adds a separate file-replace effect, and graph rendering adds file export. Computing effects does not enforce grants or classify embedded command/provider effects. Three metadata handlers actually list, describe and search the compiled entries. Cursor identity binds the immutable build, operation and filters; pagination and ranking are deterministic. Catalog pages also stop at conservative encoded-byte and parser-event budgets, with a cursor for every remaining descriptor. JSON Schema documents are the explicitly declared extensible objects in descriptor output. The independent checker validates each embedded input/output schema separately.

This development fixture advertises zero public operational tools. The other 197 declarations remain planned and reject invocation. Metadata dispatch only permits broker inspection handlers without conditional effects. Alias/parity bindings, authenticated broker/connector transports, integrated workers and real debugger operations remain later work; successful metadata tests do not close those gates. Case selection and listing still use the single tests/run_tests.py launcher.

Compiled tool schemas reuse declared root-local `$defs` and `$ref` definitions. The native validator covers its explicit schema dialect, checks every declared node before validating input, rejects undeclared/remote references and unsupported keywords or patterns, and bounds reference traversal and uniqueness comparisons. Negated constraints reject zero allocation/region sizes while retaining exact uint64 strings; malformed or cyclic negated references fail closed. The independent validator checks the compiled schemas and compares valid/invalid lifecycle, execution, inspection and memory inputs and outputs. This native dialect is intentionally restricted to the schema constructs used by the owned registry.

Execution contracts distinguish target pause from epoch/thread-sensitive steps and preserve new-event cursors, stop reasons, exception handling and suspend ownership. Inspection contracts include wide register bytes/aliases/SIMD lanes/feature validity, explicit x32 SEH and x64 unwind routes, pure-provider expression requirements, recursive typed fields and stack/ABI uncertainty. Memory contracts retain read spans/holes, expected-byte comparisons, actual write/restoration observations, owned allocations, per-page protection and hashed artifact/layout validity. Their schemas define data shapes; semantic consistency, provider purity, target width, grants, leases and actual postconditions still require the planned native owner handlers.

Breakpoint contracts distinguish all five current native kinds and preserve full conditions/actions/logging, hit counts and actual trap/range/slot state. Hardware execute size is one; data sizes are 1/2/4/8. Resolved alignment, target architecture, range overlap and embedded callback permissions require native preflight. Trace contracts require at least an instruction or wall-time ceiling and retain actual execution/job/recorder/index state, source hashes, entry counts and paging. Stopping an owned trace uses its target/trace identity; it does not require an invented prior pause or a new mutation lease.

Disassembly and pure encoding use explicit architecture, source bytes/origin and exact instruction/boundary metadata. Tracked runtime patches preserve originals/replacements, immutable revisions, breakpoint overlaps, readback and restoration. File plans retain source hashes, admitted offsets/RVAs and authenticated digests; publication/undo records include backups, journal state, outside-plan preservation and signature impact. Replacement exports require an expected destination hash. A published hash is not proof that a PE runs; runtime verification remains explicit. These are contracts for later native operations, with no new executable debugger/file handler installed.

Module/symbol/analysis contracts retain actual load/provider identities, PE field validity, forwarded/unresolved symbols, native analysis modes and all twenty native encoding types. CFG edges preserve unresolved/external targets and partial coverage. OEP candidates require rationale and explicit verification state; a score cannot substitute for execution evidence. Graph rendering declares its additional export effect. Setting a boundary or encoding requires a lease, with actual native reread reserved for later handlers.

Annotation contracts preserve all four native categories, explicit value types, manual/automatic/provider origin and revision comparisons. Imports distinguish pinned library/file sources and require an explicit conflict policy. Database observations distinguish loaded/saved versions, dirty state and actual hash/source/category counts; unknown persistence remains explicit. Settings and favorites use a GUI owner, typed values, version comparison and effect/restart classification. Storing favorites declares configuration. Actual grants, nested effects, native storage and restart persistence remain future handler gates.

Command/plugin/GUI contracts preserve actual provider/build identities, syntax/aliases, state/rights/effects, model versions, hierarchy, selections, field validation and operation-owned dialog/job state. Structured values retain exact integer bits, floating bytes and recursive typed arrays/maps. Native fields and pending OS consent remain distinct; OS consent cannot become an agent-controlled field/action. Clipboard artifact export and user-visible clipboard change declare different effects.

Eight generic/provider routes advertise native effect resolution. Their effect list is a potential set, not the permissions needed by a resolved action. The static effect calculator rejects these routes until an actual native classifier is bound; caller-supplied argument/grant fields cannot authorize them. The descriptor schema adds an optional native-classifier marker, so the two metadata output schemas expand while other existing descriptors remain unchanged. Source/parser/provider schema, grants, ownership, UI/target versions, leases and actual completion still require native handlers. This development fixture opens no dialog, loads no plugin, changes no clipboard and executes no native command.

Library/script contracts preserve explicit namespace/object/revision identity, exact content hashes/chunks, optimistic revisions, recoverable trash/history, quota accounting, pinned dependencies and typed manifests. Inline source is bounded to 65,536 Unicode characters; larger source uses an authorized hash-pinned artifact. Default storage/source/artifact quotas and 1 MiB transfer chunks remain native backend requirements. Virtual paths reject traversal, ADS, reserved devices, invalid separators, trailing dots/spaces and excessive UTF-16 component/path lengths before dispatch. This lexical check does not establish safe reparse-point/file-handle behavior or durable publication.

Native scripts remain trusted debugger code; actual native IP/branches/breakpoints/errors and abort ownership require the integrated runtime. Workflow/JS declarations retain explicit execution budgets, stable step results, pinned revisions and failure policy. Validation reports executed=false. Five script execution/control routes additionally require actual native effect classification and reject unresolved authority. No runtime execution, private store, restart persistence, cancellation or OS containment is verified by these schema tests.

Job/event/artifact contracts retain exact owner/profile/operation/version, all eleven job states, pending human/native interaction, progress/steps, effects and pinned evidence. Job cancellation also requires native effect resolution; accepting cancellation cannot claim observed termination. Reconciliation reports resumedMutation=false. Uploads retain owner/expiry/quota/coverage/whole and chunk hashes; same-content retransmission and pinned-reference deletion conflicts remain actual backend gates. Diagnostics retain explicit target-content selection and require credential redaction. These definitions verify no actual job, event race, publication, retention or diagnostic bundle.

The Windows launch codec produces an explicit application path, mutable Unicode command line, working directory and separate environment block from a typed launch request. `argv` excludes the executable name; the codec supplies and quotes it. `rawCommandLine` is the complete Windows command line and passes through unchanged. Environment changes preserve empty values, use null for deletion, reject name collisions ignoring case, and select inherited or replaced child environments without modifying global variables. Counts, encoded UTF-16 lengths and environment bytes are bounded before launch.

The suite's native launch reference is a controlled ordinary process that reports its actual CRT arguments, raw command line, directory, selected environment values, PID and architecture, then exits with 17. Tests start it through `CreateProcessW` with the codec's exact buffers, an explicit inherited-handle list and an owned process job. Independent intended values cover empty arguments, spaces, quotes, backslashes, commas, braces and Unicode under argv, raw and replaced-environment modes. These launches verify the common codec and fixture oracle; they do not verify a debugger-created target, attach, elevation, transport or worker lifecycle. All twenty-five selectable groups share the existing launcher.

The wire codec uses a 24-byte explicitly little-endian header with magic, version, message kind, total length, reserved flags and exact uint64 request correlation. This codec neither opens a pipe nor authenticates a claimed identity. Secured pipes, actual peer verification, connection state, cancellation and backpressure remain WP-03 work.

## Isolation and retained evidence

Each run creates a private directory beneath `%LOCALAPPDATA%/x64dbg-wbbified/Verification`. `--output` can select another directory outside the repository. Fixtures, objects, logs, patched targets, profiles and copied deployments stay there. The suite builds targets with an explicit `asInvoker` manifest for both architectures.

External phases copy the selected `WinTools/<arch>` deployment, use a new user directory and random authentication token, verify the HTTP listener PID, and retain process creation identity and loaded module hashes. Job ownership and process-specific shutdown bound cleanup to the owned debugger and its targets. Deployment hashes before and after the run verify that personal files were unchanged.

The x64 external plugin is the available behavioral baseline. The shipped x32 plugin directory has no corresponding MCP plugin; external x32 verification fails explicitly until that artifact is available. Normal fixtures and source-built native regressions support both architectures independently.

`--phase surface --surface-provider native` observes the source-built GUI in `x64dbg/bin/<arch>` directly through its native startup command. Its private deployment excludes the external MCP provider, and the fixture records the idle engine state, registered commands, GUI models, loaded native module hashes and PE architecture. Both x64 and x32 are supported. This mode verifies native GUI inventory capture; it does not provide or verify an MCP product endpoint. The default legacy surface mode retains the authenticated idle/paused capture.

Build phases use new out-of-tree CMake directories. Existing local Qt SDKs may supply the configured Qt package, while build output remains in the debugger's ignored `bin/<arch>` directory. No obsolete cached source directory is reused. Build receipts retain actual commands, source inputs and artifact hashes.

The native `cmdline_init` and `cmdline_setcommandline` fixtures have a target TLS callback and use the static MSVC runtime. Their startup assertions require a pause before that callback executes. This makes `SetCmdline` occur before the target runtime captures and parses its command line; a dynamic runtime can already have cached it in DLL initialization. Their scripts advance through at most 64 stops until the target sets `ObservedReady`, then check the exact CRT arguments, Windows arguments and command-line text. Additional DLL TLS stops cannot stand in for the target observation. The launch fixture also restarts with different explicit arguments after saving its database. Settings apply only to the isolated test profile.

`test_native_argument_oracles` requires those native fixtures to be built first. It launches the exact source-built executables normally with `WININSPECT_TEST_NORMAL=1` only in their child environment. They emit their captured values as ASCII fields with UTF-16 bytes represented in hex and exit instead of breaking. The checker supplies Unicode, embedded quotes and a trailing backslash independently, compares both argument parsers and the complete raw command line, and records actual process identities and executable/output hashes. Omitting the environment selection preserves their debugger observation break. `--case test_fixture_oracles` remains available for the five independently built standalone fixtures.

Evidence includes requests without authentication headers, catalog contracts, target markers, compiler output, fixture hashes, process modules and verification summaries. Failed and unexecuted requested cases remain visible. A contracts or inventory pass verifies capture/reconciliation; it does not claim that the external tool's behavior or a native replacement is correct.

## Native log compatibility

The inherited regression runner recognizes both upstream `[x64dbg-test]` and fork `[wi-test]` final markers. A reported failure remains a failure; successful parser recognition cannot override a failed assertion, missing final marker, timeout or unsuccessful process exit. Existing native drivers and checker modules remain authoritative for their individual bundles.

Native test scripts are staged with `configure_file(COPYONLY)`. CMake tracks their contents and refreshes the runtime copies when a script changes, including builds that require no C++ recompilation. Tests therefore execute the current source script instead of a copy left over from the last link step.

The native phase creates each discovery and regression runner suspended, assigns it to an owned Windows job, and then resumes its startup thread. Closing that job also terminates any remaining descendants, including targets left after a driver failure or timeout. Receipts include the runner's PID/creation time, startup thread, actual exit result, observed terminal state and whether its job closed. Discovery has a maximum of 30 seconds; each architecture/engine batch has the selected case count times the requested per-case timeout plus 30 seconds for cleanup. A batch timeout remains a failure even if its runner had already returned zero while a descendant retained an output handle. The normal-observation environment selection is removed only from these native child environments, so an inherited setting cannot bypass the debugger break.

`python tests/run_tests.py --phase runner` checks the native runner's actual process ownership without building or launching a debugger. Controlled fixtures verify child termination after an abrupt exit, a zero-exit parent whose child holds an output pipe, delayed job assignment with no early filesystem effect, and failed assignment with no execution. Independent retained OS process handles bind PID/creation time and observe termination. The generated fixture and receipts remain in the private evidence store; `runner_checks.py` is an imported suite module.

The existing `guard_page` native fixture has a normal SEH reference selected through the same child-only environment setting. Select it with `--phase fixtures --case test_native_guard_page_oracles` after building.

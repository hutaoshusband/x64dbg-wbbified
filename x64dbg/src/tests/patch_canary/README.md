# Runtime patch reference

This controlled x64/x32 target calls an assembly function with exact original bytes `b8 07 00 00 00 c3`. Its caller clears EAX before each real CALL. Mode 1 executes three calls; normal execution returns 7/7/7 and exits with 21. Mode 2 executes one call and exits with its actual value. The normal environment requires `WININSPECT_TEST_NORMAL=1` and `WININSPECT_TEST_PATCH_MODE=1` or `2`; invalid normal selection exits with 238. Unselected debugger execution exits with 239.

The native reference selects mode 1 with separate untracked data writes at the actual executable entry. It observes the first software-breakpoint hit and executes the original MOV and RET. While paused at the second target barrier with that breakpoint armed, pure encoding verifies `mov ax,0x2a` and two relative JMP origins without modifying memory or tracking. Invalid syntax and 256-character text reject without modification. The native overlong-text rejection currently has no error text; the receipt preserves that fact.

Tracked assembly then installs `66 b8 2a 00` with explicit NOP fill at offset 4. Native logical reads show the changed first opcode; an independent OS read still sees the INT3 trap. Four patch entries retain the exact original and installed bytes. A real breakpoint hit, MOV, NOP and RET produce 42. The inclusive native restore range restores all five instruction bytes while retaining the breakpoint. The third actual hit executes 7. Target values and markers are 7/42/7 and original/patched/original; the observed process exit is 56.

The common launcher exposes `--phase fixtures --case test_native_patch_oracles --arch all --engine all` and `--phase native --case patch_canary --arch all`. The fixture checker independently admits the PE exports, exact CALL/clear/return instructions, executable raw mapping and source hash. It compares target identities, logical/raw snapshots, branch origins, original patch bytes, actual callbacks, markers and process exit. Corrupted evidence controls supplement real execution checks. Profiles and receipts stay outside the repository; the source executable remains unchanged.

This establishes the bounded software-breakpoint runtime reference. Hardware/memory breakpoint overlaps, oversized installed-span policy, multi-range atomicity, failed writes/restoration, compare conflicts and persisted files remain separate roadmap gates. This bundle provides no operational MCP handler.

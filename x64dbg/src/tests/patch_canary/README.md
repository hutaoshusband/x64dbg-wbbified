# Runtime patch reference

This controlled x64/x32 target calls an assembly function with exact original bytes `b8 07 00 00 00 c3`. Its caller clears EAX before each real CALL. Mode 1 executes three calls; normal execution returns 7/7/7 and exits with 21. Mode 2 executes one call and exits with its actual value. The normal environment requires `WININSPECT_TEST_NORMAL=1` and `WININSPECT_TEST_PATCH_MODE=1` or `2`; invalid normal selection exits with 238. Unselected debugger execution exits with 239.

The native reference selects mode 1 with separate untracked data writes at the actual executable entry. Software, hardware and memory variants observe three hits at the same source function and execute the original MOV and RET. The six-byte function occupies its own page in the `PCAN` image section, separate from the caller and target barriers. While paused at the second target barrier with the selected breakpoint armed, pure encoding verifies `mov ax,0x2a` and two relative JMP origins without modifying memory or tracking. Invalid syntax and 256-character text reject without modification. The native overlong-text rejection currently has no error text; the receipt preserves that fact.

Tracked assembly then installs `66 b8 2a 00` with explicit NOP fill at offset 4. Native logical reads show the changed first opcode; an independent OS read sees INT3 only in the software variant. The hardware variant verifies its actual OS debug-register slot, enable and access/length bits. The memory variant verifies its exact one-byte execute range and actual OS page protection. Four patch entries retain the exact original and installed bytes. A real breakpoint hit, MOV, NOP and RET produce 42. Seven individual steps compare native register dumps and independent OS contexts with the source instruction pointer and known accumulator value. The inclusive native restore range restores all five instruction bytes while retaining the selected breakpoint. The third actual hit executes 7. Target values and markers are 7/42/7 and original/patched/original; the observed process exit is 56.

The memory variant also arms execute-memory and overlapping software breakpoints on a separate committed page followed by a reserved inaccessible page. The target fills its first page with `5a` and seals it with execute/read protection before memory trapping removes execute permission. The reference resolves the actual selected backend's `MemoryWriteSafe` export and requests 4,097 bytes of `5b`. The backend must reject full success and restore the memory trap. The checker verifies the actual written prefix independently with OS reads, the retained raw INT3 at offset 16 and its updated logical original byte. Clearing both breakpoints must restore the actual prefix bytes and original execute/read protection. GleeBug's page-bounded writes produce a complete 4,096-byte prefix followed by failure at the reserved tail. This checks truthful partial effects and protection/software-cache restoration; it does not establish transactional rollback of changed partial bytes.

The common launcher exposes `--phase fixtures --case test_native_patch_oracles --arch all --engine all`. Native bundle cases are `patch_canary`, `patch_canary/hardware` and `patch_canary/memory`. The fixture checker independently admits the PE exports, exact CALL/clear/return instructions, isolated executable raw mapping and source hash. It compares target identities, logical/raw snapshots, breakpoint metadata and OS protection/contexts, branch origins, original patch bytes, actual callbacks, markers and process exit. Corrupted evidence controls supplement real execution checks. Profiles and receipts stay outside the repository; the source executable remains unchanged.

This establishes the bounded nonsingle-shot software/hardware/memory runtime reference and failed-write protection restoration. Single-shot variants, oversized installed-span policy, multi-range atomicity, changed-byte rollback, restoration failure, compare conflicts and persisted files remain separate roadmap gates. This bundle provides no operational MCP handler.

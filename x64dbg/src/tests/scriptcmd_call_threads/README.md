# Thread execution reference

The default target and `test.txt` retain the original nested script-command callback behavior. `test.threads.txt` runs two fresh thread-reference sessions, first with the original register values and then with a selected worker's accumulator changed to `2468ACE0`.

Each worker is created suspended, released once, and signals its own start barrier before the target applies an extra suspension to worker 0. Both start events stay unset until the real ready stop. The debugger adds and releases one suspension of worker 0. Worker 1 then executes while worker 0 remains held by the target's earlier suspension. After worker 1 has returned 82 and disappeared from the native thread list, the target obtains a previous suspend count of 1 and balances that query's added count. It also observes that worker 0 has not entered or completed its code. Releasing the target's remaining count returns 1 and lets worker 0 execute and return 81.

The native checker compares target PID/TID/creation observations with live Windows handles, `GetThreadTimes`, raw creation/exit debug events and the bridge thread list. Thread selection uses the list's current thread and the actual OS instruction pointer, accumulator and stack pointer; `DbgGetThreadId()` is the event thread in this source and cannot identify an explicit selection. The fixture keeps every worker handle alive until target exit and frees bridge list buffers after each command.

The paused native list's suspend count can include a common stop offset. This reference admits only an observed offset of 0 or 1 and checks it against balanced, paused Windows `SuspendThread`/`ResumeThread` return values for each exact live worker. It never treats that offset as an owned suspension. The target's own later count of 1 and final release of 1 provide a separate resumed-process outcome. Older Windows paths and other hosts still require their own runtime proof.

At the two distinct MASM stop instructions, the workers have accumulator seeds `10203040` and `50607080`. The following real instructions store the accumulator into separate target cells before their counters become 11 and 22. The changed session must store `2468ACE0` only for worker 1. Selecting the main thread and held worker after that write must preserve both of their captured OS contexts. Actual worker returns, final target stores, counters and exits 87/88 complete the native reference.

Normal `WININSPECT_TEST_NORMAL=1` plus the exact `WININSPECT_TEST_THREAD_MODE=1` runs the baseline with exit 87. Invalid normal mode selections exit 238; omitting normal selection preserves the original target. The sole `tests/run_tests.py` launcher imports `thread_checks.py`, admits the architecture and exact seed/store/return instructions from the source PE, and checks all thirty output fields, the actual owned PID/startup thread, process creation bound and unchanged file identity.

This is a reference for native thread behavior and future A-17/A-27 acceptance. It does not implement an MCP suspend owner ledger, mutation leases, stale thread handles, thread-ID reuse policy, or cross-client grants.

The original `attach_pause` drivers are an additional comparison. They pass on both architectures and engines in this reference's hiding-off/TLS-off profile. On the exercised x64/TitanEngine hiding-on profile, the parked-worker debug string and repeated break-in checks fail even with TLS callbacks off. Hiding off with TLS callbacks on passes. The retained controls identify the profile boundary without an engine workaround; hidden attach/pause remains an open product gate.
